# Check catalog

`checks/catalog.json` is the scoring spec. The agent evaluates every criterion with Read, glob, and grep only. Do not install packages. Do not run `npx`. Do not run tests, linters, or scanners.

The seven pillars are Style & Validation (`style-linting`), Testing, Documentation, Developer Environment, CI/CD, Code Health, and Security. Display names are user-facing; scoring keys are the ids. Do not add a ninth pillar.

v1 skips `requiresLLM` criteria. Those are a third state: skipped, excluded from the denominator, not fails. Keep `v1SkipLLM`.

## How to evaluate a row

1. If `requiresLLM` is true, mark skipped.
2. Else look for files in `anyFiles` / `anyGlobs` (file or directory presence).
3. Else read listed files and grep `fileContains` / `fileRegex` / `ciGrep`.
4. Else apply special fields: `minBytes`, `tsconfigStrict`, `languagesPass`, `packageJsonPath`, `makefileTarget`, `lockFileFreshDays`, `testFiles`, `ciFiles`.
5. Presence of config is a pass. Never execute the tool the config describes.

Well-known config filenames in `anyFiles` / `fileContains` (no slash) match at the repo root or any walked path with that basename, so `docs/CODEOWNERS`, `packages/app/AGENTS.md`, `apps/web/biome.json`, `packages/lib/tsconfig.json`, and `assets/eslint.config.js` count without listing every monorepo path. No-slash globs such as `eslint.config.*` / `.eslintrc.*` / `.prettierrc.*` / `vitest.config.*` / `jest.config.*` match the basename at any depth for `linter`, `formatter`, and `test-framework`. Other ids keep no-slash globs root-anchored (`*.csproj` matches `Lib.csproj`, not `Src/Lib/Lib.csproj`; a vendored `deps/**/*.sln` is not a `setup-script`). Exact relative paths (`.cursor/environment.json`, `.github/CODEOWNERS`) stay exact; slashed globs still use the walked file list. `env-documentation` skip signals stay repository-root only (nested `sample/**` / `examples/**` / `integration/**` compose does not force the check); a nested `.env.example` may still pass as a real example file. `IGNORE_DIRS` (`node_modules`, `vendor`, `dist`, `build`, `.git`, `coverage`, and the rest) still apply, so `node_modules/foo/tsconfig.json` does not count.

`ai-context` looks for `AGENTS.md`, `.github/AGENTS.md`, `CLAUDE.md`, `.cursor/rules`, `.cursorrules`, `.github/copilot-instructions.md`, `GEMINI.md`, `.github/instructions/**/*.md`, `.windsurfrules`, and `WARP.md`. `AGENTS.md` is the preferred first-hit when both `AGENTS.md` and `CLAUDE.md` exist. Do not add LLM scoring.

`issue-templates` is L3 Documentation. It passes on `.github/ISSUE_TEMPLATE.md`, a file named `.github/ISSUE_TEMPLATE`, any walked file under `.github/ISSUE_TEMPLATE/` or `.github/PULL_REQUEST_TEMPLATE/`, or `.github/PULL_REQUEST_TEMPLATE.md` / `.github/pull_request_template.md`. `docs/ISSUE_TEMPLATE.md` is not GitHub's contract path. An empty `.github/ISSUE_TEMPLATE/` directory is not a hit. First-hit prefers a form (`bug_report.md` / `Bug_report.yml` / `formatting.md`) over the GitHub chooser sidecar `config.yml` / `config.yaml` and over `.github/PULL_REQUEST_TEMPLATE.md` when both exist; the shallowest form wins. A config.yml-only tree still passes and names that file. A PR-template-only tree still passes and names that file.

`linter` is language-native. ESLint and Biome are both first-class JS/TS linters: a root `biome.json` / `biome.jsonc` or package.json `"biome"` passes without ESLint, and `eslint.config.*` / `.eslintrc*` / package.json `"eslint"` passes without Biome. package.json `"standard"` / `"xo"` and `"oxlint"` also count. Go uses golangci-lint (`.golangci.yml` / `.yaml` / `.toml` / `.json`); a Makefile or `go.mod` mention is not enough. Java `pom.xml` Error Prone (`errorprone` / `error_prone` / `error_prone_core`) counts. Rust Cargo.toml `[lints.clippy` / `[workspace.lints` / `[lints.rust` counts; `Cargo.toml` alone does not, and rustfmt is not a linter. Formatters (Prettier, Black, rustfmt, gofmt, clang-format, dprint, `.clang-format`, Spotless, php-cs-fixer, `.formatter.exs`) are not linter hits. When several product-tree linter configs exist, report the shallowest (fewest path segments; repo-root `eslint.config.js` / `.eslintrc*` / `.golangci.yml` wins over `tests/fixtures/...`). Hits under a whole path segment named `fixtures` / `testdata` / `assets`, under consecutive `tests/format`, or under docs samples (`docs` / `doc` plus `sample` / `samples` / `example` / `examples`) are not first-hit when another product-tree config exists; an assets-only, tests/format-only, fixtures-only, or packages-only linter still passes. A Mix tree whose only eslint is `assets/` still passes `linter` — do not fail Elixir because a JS sidecar exists. Do not add `packages` to ignorePathSegments. Do not reject empty linter configs. `editorconfig` skips when `linter` already passes (drop from the L2 denominator, third state, not a pass). If `linter` fails or is skipped, `editorconfig` still fails when `.editorconfig` is missing and passes when it exists. Do not skip `editorconfig` merely because a formatter exists. Do not dummy `.editorconfig`.

Go, Rust, Java, Kotlin, C#, and Swift auto-pass `type-checker` when a language manifest is present (`go.mod`, `Cargo.toml`, `pom.xml`/`build.gradle`, `build.gradle.kts`, `*.csproj`/`global.json`, `Package.swift`); stray `*.go` files do not count. `Package.swift` is not a Swift manifest when the tree is C++/CMake-dominant (`CMakeLists.txt` or `*.cpp`/`*.hpp` sources and no `*.swift` sources); an SPM sidecar in a C++ repo does not languagesPass as Swift. Go, Rust, and C# auto-pass `formatter` the same way. That is a language default, not a subprocess. Do not auto-pass `formatter` merely because `mix.exs` exists. `formatter` also passes on a root `.dprint.json`, `.dprint.jsonc`, `dprint.json`, `.clang-format`, `.swift-format` / `.swiftformat`, `.scalafmt.conf`, `.php-cs-fixer.php`, `.style.yapf`, `.formatter.exs`, or pom/gradle Spotless. Empty formatter configs do not count. Hits under a whole path segment named `deps` / `vendor` / `third_party` / `third-party` (and similar vendor trees) do not count; `examples/.prettierrc` still can. A product-tree hit wins even if a vendored file also exists. Formatter first-hit is the shallowest product-tree path (fewest path segments; repo-root `prettier.config.js` / `.prettierrc` wins over `tests/integration/.prettierrc`). Hits under `tests/format` / `assets` / docs samples are not first-hit when another product-tree config exists (root `.prettierrc` over `tests/format/.prettierrc`); a tests/format-only or tests/integration-only config still passes. Do not skip `formatter` merely because a linter exists. `type-checker` passes on a root `tsconfig.json` (existence, not `strict: true`) or mypy/pyright/ty/basedpyright files, and skips (drops from the L1 denominator) when none of those apply: JavaScript without `tsconfig.json`, Python without mypy/pyright/ty/basedpyright / `[tool.mypy]` / `[tool.pyright]` / `[tool.ty]` / `[tool.basedpyright]`, and similar. `type-checker` first-hit among `tsconfig.json` / `jsconfig.json` defers a path with a whole segment named `test` / `tests` / `spec` / `__tests__` / `fixtures` / `testdata` when another tsconfig exists outside those segments (`packages/typescript/tsconfig.json` over `packages/typescript/test/tsconfig.json`, `packages/foo/tsconfig.json` over `fixtures/tsconfig.json`). A test-only tree still passes. A fixtures-only or testdata-only tree still passes. Nested product tsconfigs still count. `test-framework` first-hit prefers the shallowest product-tree path over sample / examples / docs samples (repo-root `vitest.config.ts` / `jest.config.js` / `tests/conftest.py` / package.json over `sample/01-cats-app/vitest.config.e2e.mts` or `examples/javascript/tests/conftest.py`). A sample-only tree still passes. `test-framework` first-hit among `vitest.config.*` / `jest.config.*` defers a basename containing `coverage` / `coverage.` / `integration` when another product runner exists (`vitest.config.mts` over `vitest.config.coverage.mts` / `vitest.config.integration.mts`). A coverage-only or integration-only tree still passes. When the tree is Mix/Elixir-primary (`mix.exs` present and `**/*_test.exs` / `**/*_spec.exs` / `test/test_helper.exs` exist), first-hit prefers those ExUnit files over `jest.config.*` / `vitest.config.*`. A JS-only jest tree still passes. A Mix tree with only jest (no exs tests) still passes on jest. `test-framework` also passes on `*Tests.csproj` / `*Test.csproj` (same runners as `test-script`) or a `*.csproj` that contains `xunit` / `nunit` / `MSTest`. First-hit among those Tests projects reuses the `test-script` defer (`Newtonsoft.Json.Tests.csproj` over `Newtonsoft.Json.FuzzTests.csproj`). A Fuzz-only tree still passes. Product `Foo.csproj` is not a framework. `test-framework` first-hit that names a test file prefers product-language tests over a sidecar language: when `detectLanguages` includes typescript/javascript, `**/*_test.go` is not first-hit when a product-language runner exists. A Go-only tree still passes. `test-framework` package.json `fileContains` matches unquoted `node --test` so compound scripts like `node --test && …` count; quoted `"node --test"` misses those because after `--test` comes space then `&&`, not a closing quote. Rust `test-framework` needs `**/tests/**/*.rs`, `**/*_test.rs`, or Cargo.toml `[[test]]` — `Cargo.toml` alone is `test-script` (`cargo test`), not a framework hit. `test-files-exist` uses `**/tests/**/*.rs` so `pkg/tests/foo.rs` counts; `test/**/*.js` covers mocha `test/router.js`. Mix `**/*_test.exs` / `**/*_spec.exs`, Scala `**/*Spec.scala` / `**/*Test.scala` / `**/*Suite.scala` / `src/test/**/*.scala`, Ruby `spec/**/*_spec.rb` / `**/test/**/*_test.rb` / `test/test_*.rb` / `**/test/test_*.rb`, and C++ `**/*.tests.cpp` / `test/**/*.cpp` / `**/tests/**/*.cpp` plus the same shapes for the `.cc` and `.cxx` extensions (`**/*_test.cc` / `**/*_test.cxx` / `test/**/*.cc` / `test/**/*.cxx` / `**/tests/**/*.cc` / `**/tests/**/*.cxx`) count language-native suites (Catch2 `*.tests.cpp`, nlohmann `tests/src/unit-*.cpp`, minitest `test/models/user_test.rb`, Rails-style `activerecord/test/cases/base_test.rb`, Jekyll-style `test/test_site.rb`, fmt `test/format-test.cc`, gtest `*_test.cc`). `src/*.cpp` and `src/*.cc` do not. `**/test/**/*_test.rb` needs a whole `test/` path segment, so `testdata/user_test.rb` does not count. `test/test_*.rb` (and `**/test/test_*.rb`) counts Jekyll-style prefix tests; still do not add `test/test_*.rb` without the `test/` segment (`testdata/test_site.rb` / `lib/test_site.rb` stay uncounted). Do not add `**/*.cpp`. `**/` in test-files globs is slash-anchored and does not eat into the basename, so `**/test_*.py` matches `tests/test_foo.py` and root `test_foo.py` but not `add_latest_release_date.py` or `parse_test_outputs.py`. `**/*.test.*` / `**/*.spec.*` catch-alls do not count `tsconfig.spec.json` / `tsconfig.test.json` (or `jsconfig.*`); those are TypeScript/JavaScript configs, not tests. Fixtures / snapshots / `__snapshots__` path segments are ignored. Glob matching is deduped by path, so a file matched by several globs (`src/test/scala/foo/BarSpec.scala` by both `**/*Spec.scala` and `src/test/**/*.scala`, `test/router.test.js` by both `**/*.test.*` and `test/**/*.js`) counts once: `Found N test file(s)` is a distinct-path count and never lists the same path twice. The reported first hit prefers a product-suite path: files under a whole path segment named `installer` / `examples` / `abi` are not first-hit when another matching file exists, and `**/*.test.*` / `**/*.spec.*` catch-alls are not first-hit when a language-native glob also matched (Rails `activerecord/test/cases/base_test.rb` over `actioncable/rollup.config.test.js`, Phoenix `test/` over `installer/test/`, Ecto `test/` over `examples/`, nlohmann `tests/src/unit-*.cpp` over `tests/abi/`). An installer-only or examples-only or abi-only tree still passes. When `detectLanguages` includes typescript/javascript, the reported first hit prefers `*.ts` / `*.tsx` / `*.js` / `*.mjs` tests over `*_test.go` (sidecar Go tests in a TypeScript-primary tree are not first-hit). The distinct-path count still includes those Go files. A Go-only test tree still passes. The same dedupe applies to `ciFiles`, so `.buildkite/pipeline.yml` is reported once and the first-listed CI config is unchanged.

Filename casing is ignored for exactly three ids: `readme`, `contributing`, and `license`. For those, a non-glob `anyFiles` entry matches any casing of the same name, so `contributing.md`, `.github/contributing.md`, `License.txt`, `Licence.md`, and `ReadMe.md` count, and the reported hit is the casing on disk. Everywhere else casing stays semantic: the `LICENSE-*` glob is case-sensitive (`license-key.txt` is not a license), `setup-script` still wants `Makefile`, and `version-pinned` still wants `Package.swift`. Do not lowercase basename comparisons globally, and do not extend the allowlist to other ids.

`readme` also accepts `README.markdown` and `README.mkd` (Jekyll ships `README.markdown`); `minBytes` 500 still applies.

`contributing` matches CONTRIBUTING.md / CONTRIBUTING.rst anywhere in the tree, including `docs/` and `.github/`, in any casing. Empty or whitespace-only files do not count.

`license` matches LICENSE / LICENSE.txt / LICENSE.md / COPYING / LICENSES/** and similar names in the product tree, including a package path. Hits under a whole path segment named `deps` / `vendor` / `third_party` / `third-party` (and similar vendor trees) do not count. A product-tree hit wins even if a vendored file also exists. When several product-tree licenses exist, report the shallowest (fewest path segments; repo-root LICENSE / LICENSE.txt / LICENSE.md / COPYING wins over packages/*/LICENSE). A packages-only license still passes. Do not ignore `examples`. Do not add `packages` to ignorePathSegments.

`lock-file` also accepts `uv.lock`, `pdm.lock`, and `npm-shrinkwrap.json`. `lock-file` and `no-outdated-deps` share the same lock resolution: the shallowest product-tree lock (fewest path segments; repo-root `go.sum` / `package-lock.json` / `Cargo.lock` wins). Hits under a whole path segment named `examples` / `_examples` / `vendor` / `third_party` (and similar) are not first-hit when a shallower product lock exists. An examples-only lock still passes `lock-file`. Vendor trees already dropped by the walk (`vendor` in `IGNORE_DIRS`) still do not count. If none of the listed lock files exist and `detectLanguages` says Java, C, C++, Haskell, Python, JavaScript, TypeScript, or Rust, skip the check (drop it from the denominator). Python, JS/TS, and Rust libraries without a committed lock are skipped, not failed; a committed `uv.lock` or `package-lock.json` / `yarn.lock` / `pnpm-lock.yaml` / `bun.lock` / `bun.lockb` / `Cargo.lock` still counts. `pyproject.toml` is not a lockfile. Otherwise fail. `setup-script` also passes on package.json `scripts.test`, `scripts.lint`, or `scripts.build`, not only `scripts.dev`. Makefile `setup|install` and a root Makefile still pass. `Cargo.toml`, `pom.xml`, `CMakeLists.txt`, `configure.ac`, `justfile`, `Gemfile`, `mix.exs`, `composer.json`, `Package.swift`, `*.csproj`, `build.gradle` / `build.gradle.kts`, and `build.sbt` count as setup scripts; `go.mod` alone does not. `setup-script` first-hit is the shallowest product-tree path (fewest path segments; repo-root `CMakeLists.txt` / `Makefile` / package.json wins over `support/build.gradle`). Hits under a whole path segment named `support` / `android` / `examples` are not first-hit when a product setup file exists; a support-only tree still passes. `setup-script` first-hit among `*.csproj` / `*.sln` defers a basename containing `Fuzz` / `fuzz` / `Benchmark` / `bench` when another csproj exists, and prefers the product project (`Newtonsoft.Json.csproj`) over `*.Tests.csproj` / `*.FuzzTests.csproj` when both exist. A Fuzz-only or Tests-only tree still passes. `test-script` is a runner: Makefile `test`, `scripts/test` / `scripts/test.sh` / `scripts/test-*`, `*Tests.csproj` / `*Test.csproj` / `*Tests.sln`, `tox.ini` / `tox.toml` / `noxfile.py` / `pytest.ini`, or pyproject `[tool.pytest` / `[tool.tox` / `[tool.hatch.envs`. A `build.gradle` / `build.gradle.kts` or product `*.csproj` / `*.sln` is not a test runner (`support/build.gradle` is an Android NDK library; `Foo.csproj` is the product). Those stay on `setup-script`. `test-script` first-hit among `*Tests.csproj` / `*Test.csproj` / `*Tests.sln` defers a basename containing `Fuzz` / `fuzz` / `Benchmark` / `bench` when another Tests project exists (`Newtonsoft.Json.Tests.csproj` over `Newtonsoft.Json.FuzzTests.csproj`). A Fuzz-only tree still passes. `setup-script` also passes on `scripts/install` / `scripts/install.sh` / `scripts/install-*`, `setup.py` / `setup.cfg`, or pyproject `[build-system]`.

`env-documentation` skips when there is no `.env.example` / `.env.template` / `.env.sample` and the repository root has no `.env`, `.env.*`, `docker-compose.yml` / `docker-compose.yaml`, `compose.yml` / `compose.yaml`, or `.envrc`; nested `sample/**` / `examples/**` / `integration/**` compose or env files do not count. Fail only when those root env or compose files exist without an example. `version-pinned` also passes when `setup.py` contains `python_requires`, or when any walked `*.gradle.kts` / `*.gradle` file pins a toolchain (`jvmToolchain` / `JavaLanguageVersion`); empty asdf/nvm files do not count; ruff `target-version` is not a runtime pin. Language-native pins also count: Gemfile `ruby "` / `ruby '`, `*.gemspec` `required_ruby_version`, mix.exs `elixir:` / `otp:`, composer.json `"php":`, Package.swift `swift-tools-version` (not when the tree is C++/CMake-dominant), `*.csproj` `<TargetFramework`, build.sbt `scalaVersion`, stack.yaml `resolver`, `*.cabal` `cabal-version:` / `tested-with:`, and product-tree `CMakeLists.txt` `CMAKE_CXX_STANDARD` / `CMAKE_C_STANDARD` / `PROPERTY CXX_STANDARD` / `PROPERTIES CXX_STANDARD` (not under `docs/`; the helper identifier `CXX_STANDARDS` does not count). An empty Gemfile / mix.exs / composer.json / Package.swift / gemspec is not a pin. When several pins exist, report the shallowest product-tree hit (repo-root `composer.json` wins over a nested asset `package.json`). Hits under consecutive path segments `resources/exceptions/renderer` do not count (Laravel exception-page JS is not a runtime pin). A Swift-primary tree (`Package.swift` and not C++/CMake-dominant) prefers `swift-tools-version` over a CocoaPods `.ruby-version`. Pins under `testdata`, `fixtures`, a whole path segment named `sample`/`samples`/`example`/`examples`/`starter`/`starters`/`demo`/`demos`, or a whole path segment ending in `-tests`/`_tests` do not count. A hyphenated product name such as `foo-demo` or `jupiter-starter` still counts when no parent segment matches. A bare `projects` segment still counts; `documentation` is not ignored. `containerization` also passes on `.cursor/environment.json` (Cursor Cloud Agent environment). A root `environment.json` does not count. First-hit prefers `.devcontainer` / `.devcontainer/devcontainer.json` / `.cursor/environment.json` / a root `Dockerfile` / `docker-compose.yml` / `compose.yml`. Hits under a whole path segment named `tests` / `test` / `integration` / `integration_test` / `sample` / `samples` / `example` / `examples` are not first-hit when a product boot file exists (`.devcontainer/devcontainer.json` over `integration/docker-compose.yml` or `sample/05-sql-typeorm/docker-compose.yml`, `.cursor/environment.json` over `tests/docker-compose.yml`); an integration-only or tests-only compose still passes. A sample-only tree still passes. When only deferred hits remain, first-hit names the shallowest leftover (`integration/docker-compose.yml` over `sample/05-sql-typeorm/docker-compose.yml`).

## Levels

1 Functional, 2 Documented, 3 Standardized, 4 Optimized, 5 Autonomous.

Every level clears at 80% of its own counted rows, including L1. L1 Functional is readme, linter, test-files-exist, and type-checker (skip when there is no conventional checker file). license and lock-file are L2. Minimum level is 1. Non-AI counts: L1=4 need 4 (3/3 when type-checker skips), L2=13 need 11 (12 need 10 when `editorconfig` skips because a linter already passes), L3=10 need 8, L4=8 need 7, L5=1 need 1 (`bundle-analysis`). If the report would show Level 5, add the disclaimer. Do not celebrate Autonomous. Eval canvas copy prints those engine labels. A high-% repo still at level 1 because the L2 sequential gate failed gets a "would be L2 except …" line naming remaining L2 fail ids (not `l1CapReasons`; that field is only when `l1Capped` is true). `editorconfig` skips when a prescriptive linter is already configured; do not dummy `.editorconfig`. Todo ranking is already gate-first; do not lead with `editorconfig` if it is skipped.

Optional helper: `node scripts/code-readiness.mjs <repo>` applies this same catalog with Node `fs` only. No npm install.
